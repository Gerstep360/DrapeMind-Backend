# CU-17 — Sincronizar reservas y ventas pendientes

| Campo | Descripción |
| --- | --- |
| Caso de uso | CU-17 — Sincronizar reservas y ventas pendientes |
| Descripción | Enviar operaciones guardadas y recuperar sus resultados sin duplicar reservas, pagos ni movimientos. |
| Actor | Usuario autorizado |
| Canal | Web PWA / Flutter |
| Precondiciones | Hay operaciones persistidas del usuario; la sesión y suscripción permiten sincronizar. |
| Postcondiciones | Cada operación queda confirmada, en conflicto o anulada con resultado persistente. Los fallos de comunicación conservan la misma solicitud. |

## Flujo normal

1. Recuperar conexión o solicitar sincronización.
2. Consultar primero resultados del propietario.
3. Enviar cada pendiente con el mismo UUID y contenido.
4. Validar permisos, empresa, sucursal, prendas, precios y stock en FastAPI.
5. Confirmar negocio y resultado en una transacción, o conservar un conflicto sin escrituras parciales.
6. Actualizar la copia local y continuar con el siguiente pendiente.

## Flujos alternativos

- Respuesta perdida: consultar o reintentar el mismo UUID.
- Dos envíos simultáneos: registrar una sola operación de negocio.
- Sesión caducada: recuperar acceso conservando la cola.
- UUID reutilizado con otro contenido: rechazar la alteración.
